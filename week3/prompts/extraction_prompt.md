## 一、提取方法概述

Week 2 中，我们对 8 家 IPO 公司的招股说明书 PDF 执行了结构化数据提取。提取采用 **逐页模型阅读 + JSONL 输出** 的方式：将 PDF 按页切片，每页发送给模型，由模型从原文中识别认缴流量事件和股权结构快照，按预定义 Schema 输出为 JSONL 行。

## 二、核心 System Prompt 框架

### 2.1 认缴流量提取要求

```
你是一个专业的 IPO 招股书数据提取助手。请从当前 PDF 页面中提取「认缴流量」事件。

认缴流量 = 某一时间点，特定认购方向公司认购新增注册资本/股份的事件。

提取规则：
1. 每个认购事件单独一行 JSONL 输出。
2. 字段定义：
   - record_type: 固定为 "subscription_flow"
   - stock_code: 股票代码（6位）
   - company_name: 公司简称
   - pdf_page: 当前 PDF 页码
   - subscription_date: 增资日期，格式 YYYY-MM-DD；无法精确到日时用 YYYY-MM
   - batch_label: 批次标签，如"第1批"（若招股书无明确批次则留 null）
   - subscriber_name: 认购方全称
   - subscription_shares_wan: 认购数量，单位**万股**
   - subscription_amount_wan: 认购金额，单位**万元**
   - subscription_price_yuan: 认购价格，单位**元/股**（若无法确定则留 null）
   - evidence_text: 逐字引用的原文证据（必须从 PDF 原文中摘录）
   - notes: 备注（如有，如"按持股比例反推"等）

3. 单位要求：
   - 若原文写"1,571,815 股"，需转换为 157.1815 万股
   - 若原文写"20,000.00 万元"，直接记录为 20000.0
   - 严禁混用股与万股单位

4. 原文证据必须逐字引用，不得概括、改写或省略。
```

### 2.2 股权结构提取要求

```
请从当前 PDF 页面中提取「股权结构存量」快照。

股权结构存量 = 某一时点公司的完整股权分布。

提取规则：
1. 每个股东在每个时点单独一行 JSONL 输出。
2. 字段定义：
   - record_type: 固定为 "equity_snapshot"
   - stock_code: 股票代码
   - company_name: 公司简称
   - pdf_page: 当前 PDF 页码
   - time_point: 时点标识。命名规范：
     - t0: 报告期初（有限公司设立时或招股书可追溯的最早时点）
     - t1, t2, ...: 按时间顺序递增（每次增资/股权转让后的新时点）
     - 格式可附带说明，如 "t0/报告期初"、"t1/2021-03 第一次增资后"
   - equity_structure_scope: 股权结构口径（如"有限公司注册资本"/"股份公司股本"等）
   - total_shares_wan: 该时点总股本/总注册资本（万股）
   - total_capital_wan: 该时点总出资额（万元）
   - shareholder_name: 股东全称
   - shares_held_wan: 持股数（万股）
   - capital_contribution_wan: 出资额（万元）
   - shareholding_ratio: 持股比例（%）
   - evidence_text: 逐字引用的原文证据
   - notes: 备注

3. 时点命名规范：
   - 严格使用 t0/t1/t2... 的递增序号
   - 同一时点的所有股东记录必须使用相同的 time_point 值
   - 时点描述应包含时间锚点和触发事件
```

### 2.3 输出格式要求

```
输出格式：
- 每行一个 JSON 对象（JSONL）
- 严格遵循 Schema 字段定义
- 数值类型使用数字而非字符串
- 空值使用 null
- 中文文本保持 UTF-8 编码
- 如果当前页面无相关数据，输出空（不输出任何内容）
```

## 三、已知  提取风险与掉落场景

### 3.1 多页表格断裂

**风险描述**: 招股书中股权结构或增资表格常跨页。当表格在多页间断裂时，模型可能：
- 仅提取当前页可见行，遗漏跨页延续的行
- 将不同页的片段误识别为不同时点
- 列标题错位（下一页缺表头时）

**影响公司**: 赛分科技（股权结构多页）、云汉芯城（A 轮多页摊开）

**当前缓解**: 人工校对时逐页比对，将跨页片段手工合并

### 3.2 认购方序号误抽

**风险描述**: 增资表格中序号列（如"1 源峰磐赛"）偶尔被误解析为认购方名称的一部分，导致名称中出现多余数字。

**影响公司**: 赛分科技（2021-10-28 增资表格含序号列）

**当前缓解**: 人工检查 subscriber_name 字段

### 3.3 股权激励表格混入

**风险描述**: 招股书中"股权激励"或"员工持股平台"的表格在视觉上与常规股权结构表高度相似， 可能将其误识别为普通股权结构快照，导致时点编号混乱。

**影响公司**: 三协电机（员工激励对象表格）、影石创新（期权激励）

**当前缓解**: 人工审核 time_point 序列的逻辑一致性

### 3.4 单位推断错误

**风险描述**: 当原文表格列标题单位标注不明确或被截断时， 可能在「股」和「万股」之间推断错误。

**影响公司**: 赛分科技（subscription_shares_wan 单位从股误填为股 → 手工修正为万股）

**当前缓解**: 手工修复脚本 `fix_saifen_units.py`，对已知问题进行批量修正

### 3.5 时点覆盖不足

**风险描述**: 部分公司招股书对历史沿革的披露方式为概述性文字而非逐时点结构化表格，导致  提取的时点数量少于实际股权变更次数。

**影响公司**: 星图测控（仅 3 个时点）、影石创新（无独立 subscription_flow 记录）

**当前缓解**: 已在 gold standard 中标注为已知限制，未做主观补全

### 3.6 反推值的不确定性

**风险描述**: 部分公司的增资事件中，PDF 未逐项披露各认购方具体出资拆分（如"三方共同增资XXX万元"）。当前 gold standard 采用按持股比例反推分配，但反推值并非原文记载，存在不确定性。

**影响公司**: 三协电机（稳正景明/长泽创投个别股数反推）、云汉芯城（A 轮三方拆分反推）

**当前缓解**: 在 notes 字段中明确标注"按持股比例反推"及反推依据

## 四、对 Pipeline 自动化的启示

1. **单位归一化** 是最大的自动化障碍。需要为 pipeline 增加基于 evidence_text 关键词的模式匹配：若 evidence_text 中含"（股）"等列标题线索，自动触发 /10000 归一化。

2. **跨页拼接** 需要 pipeline 具备上下文感知能力，如通过 batch_label 或 subscription_date 的连续性判定相邻页面是否属于同一表格。

3. **时点自动编号** 可以基于 subscription_date 排序后自动分配 t0/t1/...，减少人工编号的工作量。

4. **分类器前置** 可帮助区分"增资表格"与"股权激励表格"，降低股权激励数据污染股权存量 Sheet 的概率。
