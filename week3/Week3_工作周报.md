## 一、本周工作概述

本周的核心工作围绕教师组会反馈展开，对前两周建立的股权结构抽取体系进行了系统性重构。核心任务可概括为"推倒重建、两路独立、碰头对比"：Gold Standard（人工标注标准答案）从招股书 PDF 逐页重建，自动化抽取流程从招股书 Markdown 或 PDF 重新运行，两条路径完全独立、互不污染，最后通过字段级对比评估定位差距。具体完成事项包括：（1）逐页核查 8 家 IPO 公司招股书，重建 Gold Standard 四类数据（认缴流量 97 条、股权存量 634 条、交叉校验 55 项、股权转让记录），总计新增发现 28 条遗漏事件与 5 笔未识别股权转让；（2）重建自动化抽取处理管道，从 7 家公司招股书 Markdown 起步完整走通章节定位-事件提取-校验-四 Sheet 输出全链路；（3）建立三层目录结构（manual_gold / auto_output / comparison），实现标准答案与自动产出的物理隔离与系统化对比；（4）将对比评估从三状态标记（match / mismatch / missing）升级为包含归因分类的十三维字段级分析，总对比记录 6,260 行；（5）完成痕迹清理并整理为两个干净 commit 提交至 week3-submission 分支。

## 三、Gold Standard 重建

### 3.1 重建方法

Gold Standard 的重建遵循以下严格方法：

**(1) 数据来源。** 仅以招股书 PDF 原文为唯一数据来源。对每家公司，逐页阅读"历史沿革"相关章节（通常为"发行人基本情况"中的"发行人设立以来的股本演变"或"历史沿革"节），在 PDF 对应页面上标注事件位置。禁止使用任何中间数据源（JSONL、Markdown 摘要等）作为标注依据。

**(2) 四个 Sheet 的定义规则。** Gold Standard 每家公司对应一个 Excel 工作簿，包含以下四个 Sheet：

| Sheet 名称 | 数据内容 | 关键字段 | 数据来源规则 |
|-----------|---------|---------|------------|
| 认缴流量 | 增资事件（出资方、认购股数/金额、出资方式、时间） | 事件序号、出资方全称、认购数量（万股）、认购金额（万元）、出资方式、发生时间、PDF 页码、原文摘录 | 从招股书"历史沿革"段落逐条提取增资具体事件 |
| 股权存量 | 关键时点的股东持股结构截面 | 时点名称、股东全称、持股数量（万股）、持股比例（%）、出资额（万元）、PDF 页码、原文摘录 | 选取设立、各轮增资后、股改、发行前等关键节点 |
| 交叉校验 | 出资额与持股比例的算术校验 | 时点、股东、出资额（万元）、持股比例（%）、总出资额、应占比例、偏差 | 以总出资额为分母，逐股东验算其出资额占比是否等于持股比例 |
| 股权转让 | 股东间股份转让事件 | 转让方、受让方、转让数量（万股）、转让价格（万元）、转让时间、转让后持股、PDF 页码、原文摘录 | 从招股书历史沿革段落逐笔提取，含转让类型标注 |

**(3) 标注纪律。** 凡是招股书未明确披露的数据，一律留空或标注"招股书未披露"，严禁推测填充。对于可以间接计算的数据（如根据比例反推股数），需在备注列标注"计算得出"并说明计算依据。PDF 页码和原文摘录必须精确到具体段落和语句，确保每条记录可追溯、可验证。

**(4) 统一单位。** 所有数量统一为"万股"，所有金额统一为"万元"。当招股书原文使用"股"而非"万股"时，进行单位换算并在备注列标注"计算得出"。

## 四、自动化流程重建

### 4.1 重建方案

旧版自动化流程（Week 2）的核心问题在于：以 JSONL 中间产物为起点，而非从招股书原文起步。JSONL 本身已是经过截断和简化的中间表示，丢失了大量上下文信息——尤其是股权转让类事件和精细的表格数据。此外，旧版流程仅覆盖认缴流量和股权存量两个 Sheet，交叉校验和股权转让完全缺失。

Week 3 的重建方案如下：

**(1) 数据源变更。** 首选招股书 Markdown 文件（由 PDF 经结构化解析得到，保留了章节层级和表格结构），Markdown 不可用时回退至旧版 JSONL。Markdown 的优势在于：保留了招股书的完整章节结构（便于章节定位）、表格以 Markdown 表格格式保留（便于表格解析）、段落完整性高（不易截断事件上下文）。

**(2) 处理管道全链路。** 处理管道包含以下四个阶段：

| 阶段 | 功能 | 输入 | 输出 |
|------|------|------|------|
| 章节定位 | 在 Markdown 中搜索"历史沿革""股本演变"等关键词，定位目标章节范围 | 招股书 Markdown 全文 | 目标章节的起始行号与结束行号 |
| 事件提取 | 在目标章节范围内，基于规则识别增资事件与股权转让事件，提取出资方、金额、时间等字段 | 目标章节文本 | 结构化事件记录列表 |
| 交叉校验 | 对每个时点的出资额占比与持股比例进行算术核对 | 股权存量数据 | 校验结果（通过/偏差） |
| 四 Sheet 输出 | 将上述结构化数据写入 Excel 四个 Sheet | 结构化记录 | Excel 工作簿（.xlsx） |

**(3) 赛分科技的特殊处理。** 赛分科技的招股书 Markdown 文件因故缺失（可能由 PDF 解析阶段的转换问题导致），无法从 Markdown 起步。处理方案为：回退至旧版 JSONL 作为数据源，但走同一套输出逻辑生成四 Sheet Excel——即在 JSONL 已有数据基础上补充交叉校验计算和股权转让占位 Sheet。股权转让 Sheet 因 JSONL 源数据中无 `equity_transfer` 类型标注，最终留空。

### 6.1 赛分科技（688758）：单位混淆 + 事件大量遗漏

**整体情况**：match_rate 约 1.1%，是 8 家中匹配率最低的公司。核心原因是数据源受限（旧版 JSONL，仅 4 条认缴流量）与 Gold Standard（23 条认缴流量 + 5 笔股权转让）之间存在巨大的条目数量鸿沟，导致约 1,780 条 mismatch。

| 具体问题 | 涉及条目数（估计） | 成因 |
|---------|---------------|------|
| 源峰磐赛单位错误 | 1 条 | 自动化照搬原文"628726股"，Gold 统一换算为"62.8726万股"，数量字段差 10,000 倍 |

**mismatch 归因**：

## 七、方法论总结

### 7.1 核心教训

从 Week 1 到 Week 3 的演进中，最核心的方法论教训可归纳为以下三点：

**(1) Gold Standard 的独立性是不可妥协的前提。** Week 2 中 Gold Standard 与自动化同源（均出自 JSONL）的错误，直接导致整个对比评估系统丧失了意义。Gold Standard 的意义在于提供一条不受自动化任何影响的、独立的基准线，Gold 与自动化之间的任何共享环节都会污染基准。正确的做法是：Gold 必须始终从招股书 PDF 原文独立标注。

**(2) 在自动填数与留空之间，永远选择留空。** 三协电机的案例表明，"创造数据"（在无可靠数据时填入估算值）比漏抽的危害更大。漏抽至少能在 comparison 中体现为 missing，从而被追踪和修复；而自动填数可能恰好与 Gold 数值偶然吻合，形成虚假的 match 假象，永远无法被发现。处理管道的核心原则应当是：宁缺毋滥。

**(3) 归因分类比原始状态标记更有价值。** Week 2 的 comparison 仅有 match/mismatch/missing 三状态，无法定位 mismatch 背后的根因。Week 3 将 mismatch 拆分为 5 类归因、missing 拆分为 5 类归因后，能够直接锁定每个问题的成因类别，为后续改进提供清晰的方向。

### 7.2 制作流程（七步法）

基于三周实践总结的完整制作流程如下：

| 步骤 | 内容 | 关键要点 | 常见陷阱 |
|------|------|---------|---------|
| 1. 选公司 | 选取 8-10 家 IPO 公司的招股书作为样本，覆盖不同板块（科创/创业/主板/北交所）和不同信息披露风格 | 确保样本具有多样性（行业、板块、股权结构复杂度） | 选同一板块的公司，缺乏对比性 |
| 2. 建立 Gold Standard | 从招股书 PDF 逐页读、逐条标注四类数据 | Gold 必须从 PDF 原文独立标注，严禁使用任何自动化中间产物；不确定的数据标注"不确定"而非硬填；所有记录带 PDF 页码和原文摘录 | 以自动化产出为基础修改为 Gold（同源污染）；招股书未披露的内容不标注"未找到"而是根据推测填数 |
| 3. 跑自动化 | 从招股书 Markdown/PDF 走完整处理管道：章节定位→事件提取→校验→四 Sheet 输出 | 自动化必须从原始招股书起步（首选 Markdown），不可从 JSONL 等中间产物开始；覆盖全部四类数据 | 跳过章节定位直接从已知段落提取；仅覆盖增资事件不覆盖股权转让；数据缺失时自动填数而非留空 |
| 4. 三层目录分离 | manual_gold / auto_output / comparison 三个目录物理隔离 | 确保 Gold 与自动化的文件不混放；comparison 独立为一个层级 | Gold 文件和自动化文件放在同一目录；Comparison 缺少独立的版本管理 |
| 5. 对比分析 | 字段级逐条对比，标记 match / mismatch / missing 及归因分类 | comparison 必须包含归因分类列；summary 必须包含细分统计和 match_rate | 仅标记三状态不做归因；summary 缺少细分统计 |
| 6. 问题归因 | 按公司逐家分析 mismatch 和 missing 的根因，提炼跨公司共性问题 | 每家写清具体案例和成因，拒绝泛泛而谈；按严重程度排序共性问题 | 只贴统计数字不做根因分析；不区分 mismatch 和 missing 的根因差异 |
| 7. 迭代 | 基于归因结果优化 Gold 和自动化 | 优先处理 P0 问题（数据源完整性、事件类型覆盖、自动填数行为）；记录每次迭代的改动和效果 | 一次性全改完导致无法回溯；修改后不复跑 comparison 验证是否改善 |

教师组会上提出的 7 条硬性要求与上述七步的对应关系如下：

| 教师要求 | 对应步骤 | 落实情况 |
|---------|---------|---------|
| Gold 从 PDF 独立标注 | 步骤 2 | 8 家公司 Gold 均从 PDF 逐页标注 |
| 自动化从原文起步 | 步骤 3 | 7 家公司从 Markdown 起步，1 家因 Markdown 缺失回退 JSONL |
| Gold 与自动化物理隔离 | 步骤 4 | 三层目录结构已建立 |
| 覆盖全部四类数据 | 步骤 2-3 | Gold 已全覆盖，自动化股权转让系统性缺失 |
| 对比评估引入归因分类 | 步骤 5 | comparison 增加 mismatch_reason 和 missing_reason |

## 九、已知局限

本阶段工作存在以下局限性，需在后续工作中正视和改进：

| 序号 | 局限 | 影响范围 | 说明 |
|------|------|---------|------|
| 1 | 自动化未覆盖股权转让事件类型 | 6 家公司 | 事件提取规则仅能识别"增资"类事件，导致股权转让 Sheet 在所有公司的自动化产出中均为空 |
| 2 | 赛分科技因 Markdown 源文件缺失，自动化基于旧版 JSONL 运行 | 赛分科技 | 与 Gold Standard（23 条增资 vs 4 条）存在巨大差距，match_rate 仅约 1.1%，三协电机和影石创新也部分受源数据限制 |
| 3 | 三协电机招股书正文无完整历史沿革章节 | 三协电机 | Gold Standard 本身即受信息披露范围的约束，t0 时点缺失、部分数据基于反推 |
| 4 | 股东名称标准化（简写↔全称）未系统化处理 | 6 家公司 | 当前以人工在 Gold 中统一使用全称，自动化未做标准化映射 |
| 5 | 日期格式未对齐 | 7 家公司 | Gold 使用中文年月格式（"2004 年 1 月"），自动化使用精确日期（"2004-06-18"），在 comparison 中被大量标记为 mismatch |
| 6 | 单位统一转换未在自动化中实现 | 赛分科技 | 自动化照搬招股书原文单位（"股"），未统一转换为 Gold 标准的"万股" |

| 8 | 归因分类仍有一定主观性 | 全部 | mismatch_reason 和 missing_reason 的归类基于本文作者对每个差异案例的人工判断，部分边界案例的分类可能存在多义性 |

| event_index | 事件序号 | 1 |
| investor_name | 出资方全称 | 黄学英 |

| source_type | 数据来源类型 | 直接披露 / 计算得出 |
| remarks | 备注 | 如需说明计算依据或不确定性 |

| 字段名 | 含义 | 示例 |

| capital_contribution_wan | 出资额（万元） | 800.00 |
| snapshot_rationale | 时点说明 | A 轮外部融资完成后 |

| 字段名 | 含义 |
|--------|------|
| snapshot_name | 时点名称 |
| shareholder_name | 股东全称 |
