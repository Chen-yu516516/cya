# Week3 问题归因分析

> 2026-07-17，基于 comparison.csv 逐字段对比结果，逐家公司分析 mismatch 和 missing 的根因。

---

## 三联锻造

### 整体情况

match 率 1.7%（6/360）。这 6 个 match 全在股东名称和少数几个金额字段上，实际有效的匹配非常有限。

### mismatch 归因

我翻了一遍三联锻造的 mismatch，核心问题是**行对齐完全错位**——人工标注按事件时间线排列（设立→股改→增资），自动化按自己识别的事件顺序排列（全是增资事件），两条线根本对不上。具体来说：

- 人工标的第 0-2 行是 2004 年设立（孙国奉/孙国敏/张松满各出资 175/162.5/162.5 万），自动化第 0-2 行却是 2007 年的温州三联增资事件。同一行号、完全不同的事件，所有列都 mismatch。
- 三联锻造的招股书历史沿革本身就短，只有 5 小段，但自动化把它拆成了 10+ 个事件（同一段文字被重复抽取），事件边界没控制好。
- 股东名称方面：人工标注用"孙国奉等全体股东"，自动化给的是"温州三联锻造有限公司"——这是因为自动化把股改那一段和增资那一段的认购方搞混了。

### missing 归因

missing 的 16 个字段主要集中在股权转让 Sheet——三联锻造招股书里确实没有发行人层面的股权转让（报告期前的转让在申报文件 4-3 里，不在招股书正文），人工标的是"无"，自动化也没抽到，这种不算真的 missing，只是字段空白。真正的 missing 是认缴流量里自动化漏标的几个字段，原因不明，需进一步排查。

### 改进建议

三联锻造算是 8 家里最简单的，自动化应该跑得很好才对。主要改进方向是事件边界控制——不要把同一个段落反复抽取成多个事件。

## 云汉芯城

### 整体情况

match 率 0.4%（7/1717）。云汉芯城是 8 家里总字段最多的（1717 个），但 match 只有 7 个，基本等于全军覆没。

### mismatch 归因

云汉芯城的核心问题是**事件事件不对齐 + 数值单位混乱**：

- 股东名称几乎全不对：人工标注用简写"深圳云汉电子"，自动化用全称"深圳市云汉电子有限公司"。7 个 match 都是碰巧不涉及名称的字段。这不是数据错误，是命名规范不一致。
- 认购数量/金额大面积 mismatch：人工标 A 轮增资的 4000 万注册资本，自动化标的却是某个后续轮次的 25 万——行对不上，数值当然对不上。
- 日期格式差异：人工用"2008 年"，自动化用"2008-05-07"（营业执照签发日），两者语义上一致但字符串不一样。

### missing 归因

82 个 missing 字段，绝大部分在股权转让 Sheet。云汉芯城有多个报告期内的股权转让（A 轮后老股转让、员工持股平台转出等），人工逐一标注了，但自动化完全没抽到股权转让事件。这不是自动化漏了几个字段，而是它根本没识别出"股权转让"这个事件类型。具体原因：自动化从 Markdown 做事件分类的时候只分了"增资"类，没有"股权转让"类的触发规则。

### 改进建议

最紧迫的是给自动化增加股权转让事件识别。其次是股东名称模糊匹配（简写 vs 全称），可以考虑在对比时做编辑距离或前缀匹配。

## 黄山谷捷

### 整体情况

match 率 0.0%（0/338）。黄山谷捷是唯一一个零 match 的公司——连股东名称都没对上过。

### mismatch 归因

黄山谷捷的情况比较特殊。它的历史沿革里有一个"以被合并方账面净资产出资"的操作，人工标注的方式是把合并后的净资产折算成注册资本，自动化直接拿账面金额填进去了，导致数值偏差很大。

- 认购方名称大面积错位：人工标"昆山谷捷"，自动化给的是"深圳赛格高技术投资股份有限公司"——这两个是不同时期的不同事件，行号完全错位。核心问题还是事件排序算法不一致。
- 日期：人工用"2012 年 6 月"（大致时间），自动化用"2021-11-11"（某个后续事件的日期），不是同一个事件。

### missing 归因

64 个 missing 字段，认缴流量和股权转让各占一半。股权转让部分，黄山谷捷招股书里有一个 2021 年 4 月的老股转让，人工标注了但自动化完全没抽到——和云汉芯城一样的问题，自动化没有股权转让事件识别能力。

### 改进建议

和云汉芯城一致：增加股权转让事件识别。此外，黄山谷捷的合并出资这种非典型操作需要特殊处理逻辑。

## 友升股份

### 整体情况

match 率 0.2%（1/402）。唯一的 1 个 match 是一个文本备注字段碰巧一致。

### mismatch 归因

友升股份的问题和前面几家类似：事件排序不对齐 + 股东名称不一致。

- 人工标注从 1992 年设立开始（徐泾工业公司），自动化从 2020 年的金浦临港基金增资开始——差了 28 年，能对上才怪。这说明自动化根本没定位到公司设立那段文字。
- 股东名称：人工标的"徐泾工业公司"是简称，自动化如果有对应条目应该也是全称。但问题是自动化的行号和人工的行号对应的是完全不同的事件，所以股东名称比较本身就没意义了。

### missing 归因

6 个 missing 字段全部在股权转让 Sheet。友升股份和三联锻造一样，招股书正文里没有发行人层面的股权转让，人工标了"无"，自动化也没抽——这不算真的 missing。

### 改进建议

友升股份的招股书历史沿革写得比较清楚（虽然跨度 30 年），自动化应该在章节定位后就覆盖所有批次。当前的问题是自动化事件抽取的排序/编号逻辑和人工不一致，导致对比时全盘错位。

## 赛分科技

### 整体情况

match 率 0.0%（0/2047）。2047 个字段，零 match。这是 8 家里最极端的情况。

### mismatch 归因

赛分科技有两个很典型的问题：

1. **单位混淆（3 处 unit_error）**：人工标的 50 万股，自动化标的是 628,726 股。差了约 12000 倍——自动化直接把原文的"628726 股"照搬过来，没做股→万股的转换。赛分科技的招股书原文用"股"，但人工为了和其他公司统一口径全部转了"万股"，这个转换逻辑自动化没做。

2. **事件时间线完全不同**：人工标的第 0 行是黄学英设立赛分有限，自动化第 0 行标的是源峰磐赛的增资。这两个事件在时间上差了十几年。自动化根本没抽到公司设立这一段。

3. 赛分科技是 8 家里历史沿革最复杂的——增资和转让缠在一起写，同一段文字里有增资也有转让。自动化的事件分类粒度不够，没法从混合段落里拆出不同事件。

### missing 归因

267 个 missing 字段（8 家里最多），分布在认缴流量（170）、交叉校验（44）、股权转让（53）。核心原因：自动化产出的字段数量和事件数量都远少于人工标注。人工逐页逐行翻了赛分科技的招股书，标注了 20+ 个增资事件和 10+ 个转让事件，自动化只抽出了其中一小部分。

### 改进建议

赛分科技是自动化能力的天花板测试案例。需要解决三个问题：① 统一单位转换（股→万股）；② 增强混合段落的事件拆分能力；③ 提高事件召回率（当前覆盖率太低）。

## 影石创新

### 整体情况

match 率 0.0%（0/808）。零 match，但情况和其他几家不太一样。

### mismatch 归因

我仔细看了影石创新的 mismatch 行，几乎全部都标记为"文档标注差异"——原文证据不同、PDF 页码不同、批次标签不同。这些不是数据错误，是自动化在搬运原文时用了完整段落、人工只摘了关键句。

真正值得关注的是：影石创新的认缴流量 Sheet，人工标注有数据，但自动化产出全是空的。这说明自动化压根没从影石创新的 Markdown 中识别出任何增资事件。

### missing 归因

28 个 missing，其中 16 个是章节定位失败——自动化在影石创新的招股书 Markdown 中没找到"历史沿革"或"发行人设立以来的股本和股东变化"章节。另外 12 个是事件未识别：章节定位失败导致后续的事件提取全部落空。

具体原因是：影石创新的招股书 Markdown 格式和其他 7 家不太一样（可能是 PDF 解析时的格式差异），自动化的章节定位规则没匹配到对应的标题。

### 改进建议

章节定位规则的鲁棒性需要增强——不能只依赖固定的章节标题关键词匹配，应该加一个模糊搜索的兜底逻辑。

## 三协电机

### 整体情况

match 率 0.8%（3/367）。

### mismatch 归因

三协电机有一个特殊难点：它的招股书正文里根本没有完整的历史沿革。我是从发行前股东表和定向发行章节（第 35-39 页）拼凑出来的，t0 时点直接缺失。自动化从 Markdown 做章节定位时显然也遇到了同样的问题——它没找到标准位置的历史沿革，于是从别的章节捞了数据。

- 认购方名称：人工标"稳正景明"（简写），自动化标"深圳市稳正景明创业投资企业（有限合伙）"（全称）。字符串长度差了 10 倍，但指的是同一个实体。
- 数值：人工标"未披露"的地方（因为招股书确实没写），自动化硬填了一个数字（352.6786 万股、1580 万）。这种自动化"创造数据"的行为比漏抽更危险。

### missing 归因

23 个 missing，分布在交叉校验（9）和股权转让（14）。交叉校验的 missing 是因为自动化产出的字段结构和人工不一致（自动化用列式校验、人工用行式校验）。

### 改进建议

两个关键改进：① 自动化不应在数据缺失时强行填数字——应该留空并标记"未披露"；② 股东名称的缩写-全称映射需要建立对照表。

## 星图测控

### 整体情况

match 率 4.5%（10/221）。虽然绝对值很低，但在 8 家里已经是最好的了。

### mismatch 归因

星图测控的 match 率相对较高，主要原因是它的事件数量少、结构简单，自动化的事件排序和人工基本一致。但 mismatch 依然集中在几个老问题上：

- 股东名称：人工标"四方股份"，自动化标"北京四方继保自动化股份有限公司"——又是简写 vs 全称。
- 认购数量：人工标 434.0 万，自动化标 279 万——原因不明，需进一步排查。
- 日期：人工用"2016 年 12 月"，自动化用"2016-12-14"，和前面几家一样。

### missing 归因

33 个 missing，股权转让占 14 个——还是老问题，自动化没做股权转让事件识别。认缴流量的 16 个 missing 是自动化漏标的部分字段。

### 改进建议

星图测控的问题比较集中、好修。优先做三件事：① 股东名称模糊匹配；② 日期格式统一；③ 股权转让事件识别。

## 跨公司共性问题

1. **事件行对齐偏差（8/8 家）**：自动化产出的行顺序与人工标注不一致，逐行对比时大量错位。根本原因是两者的事件排序逻辑不同——人工按时间线，自动化按自己的识别顺序。后续对比应该引入事件级别的模糊匹配，先确定"这是同一个事件"再做字段对比，而不是机械地按行号比。

2. **日期格式不统一（7/8 家）**：人工用"2004年1月"，自动化用"2004-06-18"。前者是大概月份，后者是营业执照签发日——语义上都是对的，但字符串不一样。需要在对比时做日期模糊归一化。

3. **股东名称简写 vs 全称（6/8 家）**：人工习惯写简称（"稳正景明"），自动化搬运全称（"深圳市稳正景明创业投资企业（有限合伙）"）。需要建立简写-全称对照表或引入模糊匹配。

4. **股权转让事件系统性缺失（6/8 家）**：自动化从 Markdown 做事件分类时只分了"增资"类，没有"股权转让"类。这是最大的功能缺口。

5. **赛分科技的单位混淆**：自动化直接照搬原文单位（"股"），没做统一的万股转换。所有有类似问题的公司都需要加一条单位归一化步骤。

6. **自动化"创造数据"**：三协电机中有明显的人工标"未披露"而自动化硬填数字的情况——在数据缺失时不应强行填空，应该留白并标记。
