## 一、规则提取 vs  提取的能力边界

### 1.1 什么是「规则提取」

在本次任务语境中，「规则提取」指不依赖 提取模块 阅读理解，而是通过正则表达式、PDF 表格解析工具（如 Camelot/Tabula）、关键字段匹配等确定性方法直接从 PDF 中提取结构化数据。

### 1.2 当前 处理管道 的实际提取方式

当前 Week 2 的提取方式为 **提取模块 逐页阅读 + 结构化输出**，不是纯规则提取。但 Auto Pipeline（Week 3）在模拟「自动化能做什么」的场景，其核心是规则校验而非规则提取。

以下分析基于「如果完全用规则（不用 ）能提取到多少」的假设评估。

## 三、汇总

### 3.1 规则提取可行性分级

| 等级 | 公司 | 规则可提取比例 | 特点 |
|------|------|--------------|------|
| 高 | 三协电机、黄山谷捷 | 85-95% | 表格规范、单页、单位一致 |
| 中 | 云汉芯城、影石创新 | 50-70% | 部分结构化 + 部分文字描述 |
| 低 | 星图测控 | 40-50% | 概述性文字为主、时点稀疏 |
| 极低 | 三联锻造、友升股份、赛分科技 | <30% | 跨页严重、单位混乱、多轮变更 |

### 3.2 纯规则提取 F1 估算

假设只使用规则提取（不用 提取模块），基于以上分析估算：

| 指标 | 估算值 | 说明 |
|------|--------|------|
| 精确率 (Precision) | ~85% | 规则提取的值通常准确，但部分字段会遗漏 |
| 召回率 (Recall) | ~40% | 大量数据在非结构化文字中，规则无法覆盖 |
| F1 分数 | ~54% | 规则提取的硬伤在于召回 |

### 3.3 提取模块道辅助提取 F1 估算

| 指标 | 估算值 | 说明 |
|------|--------|------|
| 精确率 (Precision) | ~62% | 赛分科技 unit 错误拉低精度；但整体可接受 |
| 召回率 (Recall) | ~85% | 提取模块 能从文字描述中提取规则无法捕获的信息 |
| F1 分数 | ~72% | 提取模块 关键优势在召回率 |

### 3.4 混合方案（规则 + 提取模块 + 人工修正）F1 估算

| 指标 | 估算值 | 说明 |
|------|--------|------|
| 精确率 (Precision) | ~95% | 人工修正补齐了单位错误和格式差异 |
| 召回率 (Recall) | ~90% | 时点不足和反推值仍有提升空间 |
| F1 分数 | ~92% | Gold Standard 目标精度 |

## 四、结论

1. **纯规则提取不可行**：8 家公司中仅 1-2 家（三协电机、黄山谷捷）能通过纯规则达到可接受质量，整体 F1 约 54%。

2. **管道提取是必要组件的**：对非结构化文字（历史沿革段落、出资额调整描述）的理解能力是规则无法替代的，F1 从 54% 提升至 72%。

3. **人工修正是最终保障**：单位归一化、反推值标注、跨页拼接等问题目前只能通过人工解决，将 F1 提升至 92%。

4. **改进路径**：短期在 处理管道 中增加后处理规则（unit auto-detect）、中期优化 prompt（few-shot 示例）、长期引入多模态表格解析。
